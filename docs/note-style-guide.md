# 单篇论文笔记写作规范

本规范用于保证仓库中的论文笔记既适合首次阅读，也适合数月后快速恢复记忆，并便于 AI Agent 持续维护和横向比较。

## 1. 写作目标

一篇合格笔记应让读者不重新通读论文，也能回答：

1. 论文解决什么问题，为什么重要？
2. 作者真正新增了什么机制、系统或观点？
3. 被更新的对象是什么，信息存在哪里、以后怎么使用？
4. 方法发生在训练时、测试时还是部署阶段？
5. 是否跨任务积累，是否更新模型参数？
6. 哪个实验最支持核心结论，证据不能证明什么？
7. 最大局限、失败模式和成本是什么？
8. 与仓库中最接近的工作有什么实质差异？
9. 对后续研究或工程有什么可迁移启发？

笔记不是按论文顺序缩写，也不是摘要翻译。它应按照以后重新理解论文所需的顺序重组内容。

## 2. 三层阅读结构

### 第一层：30 秒读懂

必须位于标题和简短资源链接之后，包含：

- 一句话总结；
- 文章性质；
- 核心问题；
- 核心机制；
- 更新对象；
- 学习阶段；
- 是否跨任务；
- 是否更新模型参数；
- 最重要结论；
- 最大局限；
- “不要误读”。

这一层之前不要铺陈作者履历、完整投稿历史或公式。

### 第二层：10 分钟理解

包含论文定位、研究问题、机制或分析框架、核心方法、实验设计、主要结果、创新、局限和相关工作。

### 第三层：按需查阅

包含公式、完整实验数据、Prompt、代码结构、作者机构、投稿状态、BibTeX 和扩展资料。

## 3. 标准正文顺序

方法型和系统型论文默认使用：

```text
30 秒读懂
论文定位
研究问题与动机
进化机制卡片
核心方法
实验设计
主要结论与证据
消融、失败案例与成本
创新点与局限性
相关工作对比
作者结论与我的判断
未解决问题与研究想法
论文外部信息
参考资料与 BibTeX
```

分析、诊断和边界研究用“分析框架卡片”替换“进化机制卡片”。综述、Position 和理论论文不强制虚构实验章节，应根据证据性质调整。

## 4. 30 秒读懂

推荐格式：

```markdown
## 30 秒读懂

> **一句话总结：** 为了解决 X，作者提出或分析 Y，通过 Z 发现 A。

| 维度 | 内容 |
|---|---|
| 文章性质 | 方法 / 系统 / 分析 / 综述 / Position |
| 核心问题 | |
| 核心机制 | |
| 更新对象 | |
| 学习阶段 | 训练时 / 测试时 / 部署时 |
| 是否跨任务 | 是 / 否 / 有条件 |
| 是否更新模型参数 | 是 / 否 / 只更新辅助模块 |
| 最重要结论 | |
| 最大局限 | |

### 不要误读

这篇论文不是……，而是……
```

要求：

- 使用自己的语言，不复制摘要；
- 只写最本质的机制；
- “最重要结论”不等于“主表最高分”；
- “不要误读”针对该方向最常见的概念混淆。

## 5. 论文定位

必须明确：

- 论文属于哪个方向；
- 是方法、系统、分析、综述还是立场文章；
- 主要改进发生在哪一层；
- 和仓库中最接近的 2–4 篇工作有什么关系。

对于 Self-Evolving Agent，至少区分：

- 模型参数更新；
- 外部 memory / experience 更新；
- prompt / context / playbook 更新；
- skill / tool / workflow / harness 更新；
- 单任务内 trajectory 搜索；
- Agent 程序或代码自修改；
- synthetic task 生成与训练。

不要只写“属于 Self-Evolving Agent”。

## 6. 研究问题与动机

按照三层组织：

1. 当前领域通常怎么做；
2. 现有方法的具体不足；
3. 本文真正要回答的问题。

用一句可检验的问题收束：

> 本文试图回答：……？

避免大段照译引言，也避免“效率低、泛化差”等空泛表述。

## 7. 进化机制卡片

方法型 Self-Evolving Agent 论文必须包含：

| 维度 | 内容 |
|---|---|
| 初始 Agent | |
| 学习信号来源 | 成功/失败轨迹、环境奖励、人工反馈、LLM Judge 等 |
| 被更新的对象 | 参数、Memory、Prompt、Skill、Workflow、Trajectory、代码等 |
| 经验形式 | 原始轨迹、规则、案例、向量、程序、权重等 |
| 存储位置 | 当前上下文、文件、数据库、模型参数等 |
| 更新时间 | 每步、每轮、每任务后、周期更新等 |
| 后续使用方式 | 检索、拼接、执行、重组、再训练等 |
| 作用范围 | 单任务 / 同分布跨任务 / 长期跨任务 |
| 是否更新模型参数 | |
| 是否需要明确奖励 | |
| 是否依赖教师模型 | |
| 主要计算与 Token 成本 | |

卡片的目的不是重复方法，而是回答“知识如何流动”。

## 8. 分析框架卡片

分析、诊断和边界研究使用：

| 维度 | 内容 |
|---|---|
| 被质疑的常见假设 | |
| 研究对象 | |
| 关键变量 | |
| 控制变量 | |
| 主要诊断指标 | |
| 核心发现 | |
| 结论边界 | |

## 9. 方法与公式

优先按照信息流或时间顺序组织，而不是照搬论文章节。每个模块回答：输入、输出、执行者、执行时间、前后连接、作者新增点和作用原因。

多轮方法必须明确时间索引，例如第 `t` 次更新影响哪一轮结果。

只保留决定方法行为的公式。每个公式后解释：

1. 计算什么；
2. 变量含义；
3. 在流程中何时使用；
4. 直观原因；
5. 近似、代价和限制。

## 10. 实验设计

围绕研究问题组织，而不是按表格顺序罗列。至少记录：

- 实验对象和 Agent 类型；
- 数据集或环境；
- 基础模型；
- baseline；
- 指标；
- 训练或更新方式；
- rollout、调用次数、memory/token budget 等预算；
- 模型、工具和环境是否一致；
- 是否依赖 LLM Judge；
- 是否报告方差、置信区间或显著性；
- 代码和复现条件。

跨论文比较数字前，必须确认任务、模型、预算和协议是否一致。

## 11. 结论—证据—边界

核心实验论文推荐使用：

| 论文主张 | 支持实验 | 最强对照 | 能证明什么 | 不能证明什么 |
|---|---|---|---|---|

重要结论进一步区分：

```markdown
### 作者的主张

### 论文证据

### 我的判断

### 其他可能解释
```

不要把作者报告、数据支持和个人推断混在一起，也不要使用“证明了所有场景”等过强措辞。

## 12. 创新、局限与失败案例

创新点建议分为：

1. 作者声称的贡献；
2. 实际新增的机制；
3. 新发现或新诊断；
4. 与最接近工作的实质差异。

去掉作者命名后，仍应能解释新增操作。新术语本身不等于创新。

除了论文自述，还应检查：

- benchmark 是否过少；
- 是否依赖特定模型家族、强教师或闭源模型；
- 是否只优化当前任务；
- 是否缺少跨任务或跨模型泛化；
- 提升是否来自更多 Token、调用次数或搜索预算；
- 是否存在数据泄漏；
- 是否依赖 LLM Judge；
- 是否缺少强 baseline；
- 是否报告方差、置信区间和失败率；
- 动态、对抗或长期环境中是否退化。

失败案例比泛泛的未来工作更有复习价值。

## 13. 成本与复现

方法论文尽量记录：

- 训练模型和执行模型；
- GPU 或 API 依赖；
- 训练数据规模；
- rollout 数；
- 单任务时间预算；
- Token / context / memory budget；
- 是否需要真实环境；
- 是否提供代码、模型、配置和数据；
- 可复现难点。

没有可靠数据时写“论文未报告”，不要估算成事实。

## 14. 作者观点与个人判断

固定使用清晰标签：

- `作者认为`：忠实记录论文主张；
- `我的理解`：用自己的语言还原机制；
- `我的判断`：评价证据、创新和边界；
- `研究启发`：可迁移到其他问题的设计；
- `未解决问题`：论文没有回答的问题。

## 15. 作者与机构信息

作者圈子信息有价值，但放在正文后部。允许记录论文首页机构、共同一作、通讯作者、官方主页中与论文直接相关的稳定方向，以及该工作在研究线中的位置。

不要根据机构名称猜测作者具体贡献，不要把实习经历当成全部机构归属，也不要使用无法核验的二手履历。

## 16. 图表规范

只保留真正帮助理解的图：总览架构、核心流程、关键结果、解释力强的消融和典型失败案例。

每张图包含：

1. 清晰 alt text；
2. 原论文图号；
3. 来源说明；
4. “这张图最重要的信息是什么”。

图片嵌入对应章节，不集中堆放。长期目标是本地化到：

```text
assets/<paper-slug>/figure-1.png
```

## 17. 链接与 BibTeX

正文顶部只保留论文、代码、项目页和当前状态。不要在 metadata、顶部、投稿章节和文末重复同一组链接。

BibTeX 使用折叠块：

````html
<details>
<summary>BibTeX</summary>

```bibtex
@article{...}
```

</details>
````

正式引用信息尚未发布时，应说明当前采用 arXiv BibTeX。

## 18. 文件名与内部链接

- 单篇笔记放在 `notes/`；
- 文件名使用英文小写短横线；
- 尽量与论文完整标题对应；
- `related_notes` 使用仓库根目录相对路径；
- 正文链接使用相对路径；
- 不创建标题不同但内容重复的笔记。

## 19. 不同文章类型的重点

- **方法 / 系统论文**：机制、信息流、训练或更新对象、实验、成本、失败模式。
- **分析 / 诊断论文**：被质疑的假设、控制变量、诊断指标、替代解释、结论边界。
- **综述论文**：分类坐标系、类别边界、覆盖范围、遗漏和组织研究路线的价值。
- **Position / Theory 论文**：核心命题、概念定义、规范性主张、可证伪预测和缺失的实证证据。

不要为了模板完整，给没有实验的文章虚构主实验。

## 20. 修改和审阅原则

每个 PR 尽量只解决一种问题：metadata、快速阅读层、正文重排、图片迁移、横向综述或自动检查。

批量修改前，先用不同类型的三篇论文试点。自动化工具不得覆盖个人判断、研究想法和图的解释。
